# muxy 0.119.3

## Fixed

- Allow touchscreen taps to reopen the software keyboard while an alternate-screen application requests mouse reports.
- Preserve physical mouse and touchpad exclusion, disabled-keyboard settings, URL-tap behavior, and remote click reporting.

## Upgrade

Install over muxy 0.119.2 using the same bootstrap variant. Package `com.termux`, version code 122. The signing certificate is unchanged:

```text
756768af514d3fa0d1c214d54dabd7b0cd088a1723a22f520b90e8e8545262ce
```

Use `apt-android-7` on Android 7 or newer, or `apt-android-5` on Android 5 or 6. Each variant includes arm64-v8a, armeabi-v7a, x86, x86_64, and universal APKs. Do not switch bootstrap variants within an existing installation.

## Verification

- The keyboard-reopening failure was reproduced on the published 0.119.2 APK. The corrected signed APK passed the same installed-app test on API 35 with Gboard beta 18.1.3.
- The installed-app test covers alternate screen alone and mouse-reporting modes 1000, 1002, and 1003. Physical mouse taps leave the keyboard hidden; touchscreen taps reopen it; exiting alternate screen preserves keyboard access.
- 2 app, 159 emulator, and 46 terminal-view JVM tests passed in debug and release.
- The 42-scenario Android connection/View/pointer suite completed without failures on API 21 x86 and API 35 x86_64. Manual-input and newer-API cases are skipped when their prerequisites are absent.
- All ten signed APKs passed signer, embedded bootstrap, API 21 native import, and 16 KiB ELF alignment verification.
- Signed upgrades from 0.119.2 preserved home-directory test data on API 21 and API 35. Shell commands, rotation/session retention, extra-arrow input, and forward deletion passed on both emulators.
- The final signed 0.119.3 API 35 APK passed keyboard reopening in alternate screen alone and with mouse-reporting modes 1000, 1002, and 1003.

Physical devices and OEM keyboard variations remain unverified. Remotly is unchanged in this release.
