# muxy 0.119.4

## Fixed

- Keep the IME editor document aligned after finishing Hangul composition and repeated Backspace.
- Send pending preedit before arrows, Tab, Home/End, forward Delete, and function keys. Publish the final editor state once and consume matching late commits once.
- Keep the next identical syllable after deletion instead of treating it as an old commit echo.

## Removed

- Remove `enforce-char-based-input` and `ctrl-space-workaround` from the settings loader and input paths. Use a text editor without legacy password flags.
- Remove active and commented occurrences of both keys from existing user `termux.properties` files and the installed example. Clean fresh bootstrap examples before installation completes. Preserve other content, line endings, and file permissions. Cleanup failures leave the original file intact and surface an error.

## Upgrade

Install over muxy 0.119.3 using the same bootstrap variant. Package `com.termux`, version code 123. The signing certificate is unchanged:

```text
756768af514d3fa0d1c214d54dabd7b0cd088a1723a22f520b90e8e8545262ce
```

Use `apt-android-7` on Android 7 or newer, or `apt-android-5` on Android 5 or 6. Each variant includes arm64-v8a, armeabi-v7a, x86, x86_64, and universal APKs. Do not switch bootstrap variants within an existing installation.

Termux addons using the shared UID must use the same signing certificate. Differently signed F-Droid, GitHub, or Play APKs are not made compatible by this release.

## Verification

- The input changes pass 159 emulator and 49 terminal-view JVM tests in debug and release.
- Eight app tests per build type cover existing behavior and properties cleanup, including continued/escaped keys, unrelated settings, line endings, malformed input, and idempotent file updates.
- Android connection/View/pointer suites report 48 scenarios each on API 21 x86, API 34 x86_64, and API 35 x86_64, with no failures. API 21 skips ten scenarios; API 34/35 skip the optional live-typing scenario when its argument is absent. Some newer-API assertions return early on older Android.
- Actual Gboard `18.4.1.985164140-release-arm64-v8a` on API 35 passes ordinary Hangul, eight touch Backspaces or injected Backspace keys followed by retyping, and all four arrows or Tab between Hangul words. Tests compare PTY bytes, including the navigation sequences.
- All ten signed APKs pass signer, manifest, checksum, embedded bootstrap, API 21 native import, and 16 KiB ELF alignment checks.
- Signed 0.119.3-to-0.119.4 upgrades pass shell execution, rotation/session retention, extra-arrow input, and forward deletion on API 21 x86 and API 35 x86_64. The API 35 signed app also passes keyboard reopening across alternate-screen mouse modes.
- An API 35 signed upgrade removes exactly the two example lines from the existing user and installed-example properties files, preserving all other bytes and mode 0600.
- The signed API 35 app with actual Gboard 18.4.1 passes eight touch Backspaces followed by `안녕 한글`, checked as UTF-8 bytes.

Physical devices, other IME versions, live Japanese/Chinese candidate IMEs, Samsung Keyboard, and arbitrary TUI bindings remain unverified. Comparative terminal history memory and throughput measurements remain pending.
