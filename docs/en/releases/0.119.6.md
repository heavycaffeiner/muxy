# muxy 0.119.6

## Fixed

Backspace beyond an empty editor could interrupt the next Hangul composition, including on the alternate screen. Gboard moved its cached absolute caret while muxy continued reporting the previous position.

After retained input is exhausted, Backspace now decreases the editor origin and stops at zero. All terminal Backspace events still reach the PTY. Submitted text is not restored as editable context. The fix does not restart the IME or normalize user text.

## Upgrade

Install over 0.119.5 using the same bootstrap variant. Package `com.termux`, version code 125. Both bootstrap variants and all four ABIs remain supported. The release certificate is unchanged:

```text
756768af514d3fa0d1c214d54dabd7b0cd088a1723a22f520b90e8e8545262ce
```

Float `0.17.0+muxy.3` pins the corrected muxy libraries and is released separately. Other addons do not embed the terminal editor and do not require an update for this correction.

## Verification

- Gboard `18.4.1.985164140-release-arm64-v8a` reproduces split Hangul before the fix after submitting context and tapping Backspace eight times. The same test passes after the change.
- Actual Gboard typing passes ordinary and alternate-screen PTY captures after eight or 30 excess touch Backspaces. Thirty deletions also cover reaching zero and continuing to delete.
- Debug and release host tests pass 159 emulator, 51 terminal-view, and eight app tests per build type.
- Android connection/View/pointer suites complete 52 scenarios without failures on API 21 x86, API 34 x86_64, and API 35 x86_64. API 21 skips 12 scenarios; API 34/35 skip the optional live-input scenario. Some newer-API assertions return early on older Android.

Alternate-screen live capture uses canonical line discipline, not a specific TUI. Physical devices, other live IMEs, and arbitrary application bindings remain unverified for this correction.
